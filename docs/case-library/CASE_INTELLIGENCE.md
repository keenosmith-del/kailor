# Case intelligence

Fifteen seeded scenarios are examples rather than discovery boundaries. Fourteen synthetic personas cover presentation, bookings, administration, content, exact application scope, fleet maintenance, new/vague situations and adverse constraints. They represent hypotheses, never observed customer outcomes.

The founder simulator runs the adaptive session/answer/chat/assessment pipeline with local inference. It records actual question titles, answers, skipped state, source and revisions in `discoveryPath`, plus persistent session evidence/messages and an immutable report. Expected/excluded services produce automated notes. Additional supplied fixture details are voluntary context after adaptive progression rather than mandatory questions. The private API accepts a bounded custom persona with `synthetic: true` as well as a seeded persona ID.

Founder evaluation records omissions, incorrect assumptions, notes and acceptable/needs_revision/rejected verdict through an owner-scoped endpoint. It preserves the automated notes. Runs generate pending simulation-source reference cases with qualitative limitations and stage/constraint patterns. They never approve themselves. The existing editable case-review API/UI requires a sanitized pattern, title and substantive notes before approval/rejection. Approval never changes source classification or invents verified results.

Only approved reusable records influence retrieval and next-step clarifications. Guests retrieve only seed definitions, never approved founder records or source sessions. Reference patterns cannot become current-session facts or create unsupported service recommendations. Sanitization still requires founder review; automatic detection of private content is not provided.

Deterministic matching considers problems +4, tools/channels +2, goals +2, scope +3, stage +2, constraints +1 and industry +1. At least one problem/goal/scope overlap and total ≥4 are required; industry or tools alone do not qualify. Return at most four with stable ID tie-breaking. Results include source, approval status, relevant factors, usefulness and limitations. Derived prose factors are identified as described signals requiring interpretation review. Cross-industry workflow matches are useful; same-industry users with different problems need not match.

Approved references add bounded clarification priority and refine recommendation next steps rather than copying answers, inferred constraints or claimed success. Integration verification approves a sanitized synthetic pattern and reruns a related persona, asserting retrieval and reference-informed steps. This demonstrates curated reuse, not automatic model training or verified real-world improvement.

`npm run evaluate` runs all 14 deterministic persona properties without database/network access. `npm run simulate` persists founder-owned sessions and pending cases. Real PostgreSQL integration tests execute all seeded runs plus custom definition/evaluation/approval/rerun workflows with isolated owners. See [iteration 003](../iterations/003-adaptive-intelligence.md) for exact results and API examples.

`CaseRetriever` is the future adapter boundary for improved retrieval. Exact option/phrase overlap remains limited; no vector database or embeddings were added. Real assessment/project/outcome ingestion, formal commercial outcome validation and full Case Lab visuals remain future work. kai research → draft → approval → publication remains a proposed workflow only.
