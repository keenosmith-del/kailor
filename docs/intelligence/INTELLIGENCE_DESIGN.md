# Intelligence design

The hybrid system shares confirmed session answers across guided discovery, conversation, Canvas and Analysis. Pure domain modules build context, rank useful gaps, evaluate readiness, retrieve approved references and produce proportionate catalogue directions. These operations do not require model calls.

`context-extraction.ts` implements limited auditable language rules for local mode. It can recognize explicit activity, channels/tools, portfolio/booking/invoice/content objectives, application requests and simplicity/budget constraints. It rejects obvious hypothetical phrasing and distinguishes website absence from absence of all channels. Derived signals stay labelled as possibilities; raw descriptions and confirmed preferences retain their provenance. Local mode is labelled deterministic guidance, not unrestricted language understanding.

The Cloudflare REST adapter remains behind `AiProvider`. Its system contract includes choice IDs, catalogue capabilities, current answers and the adaptive question/readiness. It requests concise structured candidates and useful alternatives, recognizes corrections and existing systems, and prohibits privileged operations or claims of completed work. Candidate fields/options/types and duplicate keys are validated for every provider with Zod plus question rules. Candidates remain unconfirmed evidence. A model cannot approve cases, modify prices, publish, execute tools or directly change answers.

Only explicitly enabled founder chat/alternative requests route remotely: `AI_PROVIDER=cloudflare`, `AI_ALLOW_REMOTE=true`, account ID and token are all required. Guided selections have no inference cost. Guests and simulations force local mode. Credentials stay server-side. HTTP timeouts, rate limits, malformed responses and validation failures return a safe local fallback without retries. PostgreSQL advisory-lock reservations bound calls per session/day and requested output tokens; failed attempts consume reservations.

These protections are call allowances, **not monetary or free-tier billing guarantees**. Nothing activates provider billing. Future paid inference needs account-level controls, per-model pricing, actual input/output usage, monetary reservations and reconciliation. Existing opt-in and limits were not weakened.

Assessment recommendations depend on actual descriptions, workflow evidence and explicit constraints, not industry alone. Existing providers are improved/integrated before replacing them; portfolios do not trigger AI; unfamiliar operations receive exploratory feasibility/specialist review. Manual templates and existing tools remain alternatives to custom/AI engineering. Missing pricing inputs stay manual review. Report snapshots preserve both supporting descriptions and uncertainties.

Current verification: controlled mocked HTTP tests cover contract shape, malformed output, invalid/duplicate fields, failure, timeout and 429 handling. Local configuration has no Cloudflare credentials and remote use is disabled, so **live inference remains unverified**. Confirmation gates remain necessary for hallucination protection; there is no independent factual verification service or AI-generated question planner. See [iteration 003](../iterations/003-adaptive-intelligence.md) for architecture, actual evaluation results and limitations.

## Iteration 004: evidence reliability boundary

The authoritative path is quality → response state → current resolved facets → independent evidence decision → readiness → supported recommendation. `evidence-policy.ts` does not import recommendations. Planner eligibility, API assessment preparation, conversation guidance and Canvas consume that policy. `createReport` uses the same source-backed directions; a case match cannot supply a missing user problem.

`knowledge-conflicts.ts` interprets limited current website/booking and technology preference clauses. Correction provenance includes source message/quote, rule/model basis, quality, conflicts, resolved facets and confirmation revision. Confirmed means accepted by the user, not independently verified. Historical statements remain source history; corrected facets supply the current projection. Conditional directions cite actual saved fields. Desired automation alone is described as exploration rather than proven repetitive work. Existing providers favor improvement/integration. Refused AI, website or automation directions are suppressed. Unfamiliar operational domains can receive bounded feasibility exploration; specialist clinical decisions are unsupported.

Local conversation guidance handles greetings, thanks, explanation requests, uncertainty, off-topic requests and corrections separately from extraction. Candidate facts remain pending until explicit review. The provider receives the saved authoritative plan and validated directions, including current corrections. Schema-valid JSON cannot bypass semantic checks: proposal values/quotes must be grounded in the user message, choice values must agree with deterministic extraction, duplicate or contradictory proposals and filler replies fail validation. Invalid responses, unavailable providers, timeouts and rate limits use local fallback. Legacy set-field commands remain for compatibility.

Remote inference retains founder opt-in, server credentials, atomic reservations, call/token bounds and fail-safe routing. Guests/simulations force local inference. A conservative sensitive-contact/identifier detector keeps matching founder context local before reservation. This is not complete DLP. Free-form model replies lack complete claim-level verification. No live Cloudflare call was made: provider was mock, remote disabled and credentials absent. No billing activation or model-training claim is made.

Structured diagnostics record issue codes, revision, completion, counts and fallback reasons without raw answer logging. Relevant events include input.rejected, answer/clarification/skip mutation, contradiction detection/resolution, discovery.planned, conversation.quality, assessment.blocked/created and simulation.incomplete. See the iteration log for executed evaluation results and the limited language coverage.

## Iteration 005 boundaries

Source-linked context statements distinguish confirmed description, unverified, hypothetical and superseded statements. Multiple described objectives can yield independent directions. Desired tools are not automatically current tools; tentative scope comparisons request a decision. Evidence-based service eligibility precedes `evaluateSolutions`, which adds proportionate approach comparisons, reasons, dependencies and approved-reference limitations. No case provides client facts or unsupported services. Remote requests omit chat history, website address, budget and timing and bound answer text; regex screening/output checks are incomplete defenses, not complete DLP or hallucination detection. The bounded live evaluator uses only synthetic `_test` sessions and existing opt-in/usage reservations. Live configuration currently lacks credentials/opt-in, so quality remains unverified.

## Iteration 006 context and conversational boundaries

`conversation-context.ts` selects at most twelve recent user/assistant messages within twelve thousand characters by default; `AI_CONTEXT_RECENT_MESSAGES` and `AI_CONTEXT_MAX_CHARACTERS` configure those bounds. An older range of at least the window size gets up to six provenance-labelled 400-character exact excerpts. This deterministic digest is lossy unconfirmed conversation, never evidence. No extra model call or persistence occurs. Latest input is appended once.

Policy is separate from untrusted facts/history. Readiness, corrections, pending details, skipped keys, approved-reference question hints and supported recommendation alternatives are supplied without private case titles/source sessions. Questions/historical/hypothetical clauses cannot become remote proposals merely through exact quoting. Proposals remain validated and confirmation-gated. Local ordinal resolution requires explicit numbered alternatives in recent history and otherwise clarifies. See [ADR 008](../decisions/008-bounded-conversation-memory.md). Live model quality remains unverified; no credentials/remote opt-in were present during iteration 006.

## Iteration 007 authority, retrieval and routing

Current confirmed plan knowledge and corrections override older discussion, account defaults and curated references. Persistent summaries group alternatives, decisions, questions and discussion with source IDs/ordinals, temporal/truncation labels and version/coverage revisions. Material corrections supersede summaries; rejected proposals invalidate continuity memory without automatically staling reports. No summary is generated on reads or every turn. Scoped keyword/source retrieval can recover earlier options outside the recent window. Fixed summary/retrieval bounds are documented in [ADR 011](../decisions/011-versioned-memory-lifecycle.md); these are lossy source excerpts, not validated semantic LLM summaries.

Lightweight intent rules gate explicit application actions; optional model intent/plan-proposal fields are Zod-validated and grounded. Another-business turns cannot update the active business and are excluded from later inference memory. Multiple goals in one business remain together. The ordering/customization/fulfilment dimension adds a reusable `orderWorkflow` gap without defining an industry dialogue catalogue. Historical/future scope is separated from current clauses. Explicit account defaults are not inferred from business facts.

Cloudflare receives only the active session's selected context, scoped personal memory and reviewed defaults. It never enumerates other plans. Simple greetings and plan actions are local; useful accepted questions can use authorized remote inference. Audit/response routing identifies the chosen path. Exact requested confirmed budget recall is permitted as a constraint; unsupported generated prices remain rejected. Default model is now `@cf/meta/llama-3.1-8b-instruct-fp8`; explicit existing overrides are preserved. Public model documentation and account billing considerations are linked in [ADR 013](../decisions/013-plan-aware-model-routing.md). Live inference remains unverified without credentials and opt-in.

## Iteration 008 provider boundary

The selected Workers AI model is `@cf/meta/llama-3.3-70b-instruct-fp8-fast`. The adapter requests JSON mode and accepts object or string responses. Safe reply validation is independent from proposal validation: an ungrounded extraction batch is discarded without losing a useful safe answer. Unsupported reply claims and transport/schema failures still fall back locally. Pending corrections remain explicit, source-grounded proposals; conversational yes/no never bypasses material evidence confirmation. Cleared transcripts and superseded summaries cannot enter future personal memory. Bounded live evidence and quality limitations are recorded in [iteration 008](../iterations/008-ai-conversation-and-auth.md).

## Requirement priorities and operational consulting

The [consulting intelligence iteration](../iterations/017-consulting-intelligence.md) adds an attributed, reconciled requirements projection shared by assessment, Canvas and Chat. Explicit priorities and corrections override generic suggestions; progress statuses, customer links and GPS retain distinct identities. Operational recommendations compare manual improvements, an evidence-relevant established platform category and custom engineering after a demonstrated gap. Structured model context preserves requirement priorities and decisions without slicing through serialised JSON. Reply validation rejects deferred-feature promotion, internal configuration leakage and unsupported public-business claims for internal workflows. These are inspectable deterministic safeguards; the recorded live smoke and its limitations are separate from automated contract tests.
