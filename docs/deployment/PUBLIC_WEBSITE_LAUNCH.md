# Public website launch review — 19 October 2026

This is a source-code review of the current working tree, not a penetration test or confirmation of deployed configuration. No secrets were read from `.env`; no policy, account, database or inference configuration was changed. No deployment was performed.

## Recommended access decision

For an initial limited launch, use `REGISTRATION_POLICY=closed`, disable guest remote inference with `AI_ALLOW_GUEST_REMOTE=false`, and keep `AI_ALLOW_REMOTE=false` until provider costs and intended usage are approved. **These are recommendations only; none were applied.** Existing accounts continue to sign in under closed registration. Provision limited new accounts through an approved administrative workflow; the current legacy invite option is not an invitation gate.

If the intention is to disable guest exploration entirely, a reviewed backend/edge restriction for `/api/guest` is also needed. There is currently no guest-disable environment flag. Do not assume removing a website CTA secures an API. Guest cleanup/retention scheduling, abuse response, verification/recovery workflows and privacy terms should be reviewed before broad public access.

For controlled public registration, explicitly choose `public`, confirm verification/recovery and support expectations, add appropriate edge abuse protection, decide guest policy independently and set tested inference ceilings. Do not enable access simply because anticipated visitor numbers are small.

## Hosting requirements

- Build with `npm run build`; publish **only `frontend/dist`** as static content. Never publish repository root, `design-references`, `.env`, database files or source uploads.
- Use HTTPS at `https://kailor.co.za`. Serve real static assets first. Route public paths and `/app`, `/preview`, `/sign-in`, `/create-account`, `/founder`, `/plans`, `/sessions` deep links to `index.html` through an SPA fallback. `/api/*` must reach the API, never the SPA fallback. Missing media/static files should return 404, not index HTML.
- Backend starts with `npm start -w backend` after its build. Keep database and provider credentials private; no secret belongs in a `VITE_` variable. Verify `DATABASE_URL`, `NODE_ENV=production`, `HOST`, `PORT`, `APP_ORIGIN`, registration settings and all AI settings with the owner.
- Verify migration compatibility independently against the existing database. This website iteration requires **no schema change, migration, seed or reset**.
- Cache hashed assets immutably, keep HTML revalidatable and APIs `no-store`. Confirm API Helmet/CSP and the static host's own headers, media policy and SPA routing. A restrictive CSP must accommodate React/Motion style attributes and same-origin media.
- `robots.txt` omits private routes; robots directives are not security. Add `X-Robots-Tag: noindex` to app/auth/preview responses at the static host. React applies route metadata client-side; use route-aware prerendering/HTML if full crawler/social per-page metadata is required. The initial HTML carries homepage metadata and a working mascot sharing image; replace that with an owner-approved raster social card for release.
- Perform staging account, guest, project isolation, origin rejection, role-denial, quota and cookie checks over real HTTPS. Real signed-in browser flows were not exercised in this website iteration; deterministic application suites were run.
- Obtain final visual/media/content approval, confirm the commercial availability language and access policy, review privacy/data-retention information, then request deployment approval. DNS, hosting and paid services were not changed.
