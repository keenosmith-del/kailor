# Testing strategy

Run deterministic unit tests before database tests, then typecheck and production builds. Tests validate domain behaviour rather than duplicating UI markup.

`backend/tests/unit.test.ts` covers four entry branches, professional context, conditional pruning, option/type/skip validation, complete paths for five personas, scenario completeness, evidence-gated recommendations, missing-pricing behaviour, case source/review separation, mock proposal isolation, provider gating, session/daily call limits, invalid output, timeouts, 429/500 fallback, official REST payload shape, report evidence consistency, a real PDF signature and scrypt verification.

`backend/tests/integration.test.ts` uses Supertest and actual PostgreSQL/Prisma, not an in-memory database. It covers private auth, origin checks, cookie properties, persisted answers/evidence/history, stale and concurrent revisions, explicit chat confirmation, insufficient assessment evidence, immutable reports, separate live canvas, PDF HTTP output, all fourteen synthetic runs, manual approval without source promotion, owner-scoped sessions and logout revocation.

The synthetic CLI runner is a separate product capability: it persists inspectable sessions and reports, compares expected/excluded services and records notes. Unit fixtures are shared with it. `npm run evaluate` separately reports expected/excluded services, grounded evidence and readiness for all fourteen personas. A passing synthetic regression means the implementation meets those assertions; it does not establish client satisfaction or commercial impact.

Browser inspection must include introduction, saved-session navigation, conversation, canvas, report panels, login and mobile-width layouts. Browser-only defects can survive typechecks; initial inspection caught and fixed duplicated React peer dependencies. PDF review renders all sample pages and checks margins, pagination, evidence and draft/synthetic labels.

Provider contract tests use fake HTTP responses. No live Cloudflare call, monetary billing enforcement, load test, penetration test, real-device gesture test or formal accessibility audit has been performed. Record actual execution results in the iteration log.

## Iteration 005 evaluation

`npm test` includes `contextual.test.ts` with the independently labelled fifteen-case corpus, learning-difference/negative-reference assertions, provider output/privacy boundaries and draft lifecycle checks. `npm run evaluate` preserves fourteen personas and 57 reliability cases and additionally records the independent corpus and before/after learning result under `.cache/qa/iteration005/intelligence.json`. Each corpus case states expected dimensions, forbidden assumptions, solution categories, readiness and retrieval relevance before executing the pipeline. Assertions compare behavior/categories, not exact generated prose.

`npm run test:integration` includes `contextual.integration.test.ts` and runs files sequentially because they share approved reference records and temporarily change provider configuration. It uses only the documented `_test` database and cleans owner-specific records. The expanded vertical slice exercises no-op report freshness, real corrections, concurrency, compatibility, stable questions, mocked generated-question persistence, founder source review/approval/versioning and meaningful case reuse. The learning API artifact is `.cache/qa/iteration005/learning-api.json`; it contains synthetic inputs only.

Missing configuration records live quality as unverified. Controlled mock-provider tests do not establish live model quality. Exact final counts and actual browser coverage/limitations are in the [iteration 005 record](../iterations/005-contextual-intelligence.md).

## Iteration 007 plans, memory and migration

`memory.test.ts` covers action intent boundaries, multiple goals, historical/planned clauses, category retention, superseded excerpts, temporal/current website preference, technical explanations, draft isolation, exact budget recall and ordering gaps. `plans.integration.test.ts` uses two real accounts and actual PostgreSQL/API calls for idempotent creation, optimistic rename, archive/restore, concurrent selection, multiple discoveries, independent budgets/reports/revisions, model payload isolation, plan proposals/decisions, long-history retrieval and summary lifecycle, explicit defaults, comparison authorization and the global inference ceiling across plans.

`migration.integration.test.ts` builds an isolated random schema in `kailor_test`, applies all six older migrations, inserts representative legacy sessions with a shared subject/different owners, messages/evidence/report and an unchanged credential hash, then applies the additive plan migration. It checks separate ownership/identities, unchanged content and FK rejection of cross-owner reassignment. Only that disposable schema is dropped; no database is reset.

`data/evaluations/conversations.ts` adds twenty independent multi-turn scenarios, including long conversations beyond the recent window. `npm run evaluate` preserves the earlier eight conversation scenarios, 14 personas, 57 reliability cases, 15 intelligence cases and learning checks. The new artifact `.cache/qa/iteration007/conversations.json` records turn intents, candidate facts, replies and rubric failures. This is deterministic behavioral evidence, not a natural-model quality score.

`npm run evaluate:live` remains at most three synthetic remote attempts, with existing founder opt-in/credentials and the isolated database required. It seeds older alternatives locally, tests references/comparative limitations/correction, records local baselines, actual provider output, usage/fallbacks and pending human review criteria. No paid billing is enabled. The latest executed results and browser coverage are in [iteration 007](../iterations/007-conversational-memory-and-plans.md). Generated `.cache` output is now ignored; historical tracked artifacts are left for owner-managed index cleanup.
